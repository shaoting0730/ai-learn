# 二、先理解这 10 个框架到底在竞争什么

这是视频最值得理解的部分。

以前 Agent 框架竞争的是：

> “我有多少 Tool？”

但现在 **MCP** 出现以后，Tool 正在标准化。

可以把 MCP 理解成：

> **Agent 世界里的 USB 接口。**

以前：

```text
LangChain Tool
CrewAI Tool
AutoGen Tool
Dify Tool
```

各有各的接口。

现在越来越多工具直接：

```text
                 ┌── LangGraph
                 ├── CrewAI
MCP Tool ────────┼── Pydantic AI
                 ├── AgentScope
                 ├── Google ADK
                 └── ...
```

所以：

> **“支持多少工具”已经越来越不是框架核心竞争力。**

视频认为真正的竞争逐渐变成：

```text
        Agent Framework
               │
       ┌───────┴────────┐
       │                │
   Agent怎么做       Agent怎么协作
       │                │
    Reasoning       Orchestration
       │                │
       └───────┬────────┘
               │
        Context Engineering
```

# 三、第一名：LangGraph

[LangGraph GitHub](https://github.com/langchain-ai/langgraph?utm_source=chatgpt.com)

官方定位就是 **low-level orchestration framework for stateful agents**，核心是构建有状态、长时间运行的 Agent。当前 GitHub 仓库约 37K Stars。([GitHub](https://github.com/langchain-ai/langgraph?utm_source=chatgpt.com))

### 核心思想

```text
Node
  ↓
State
  ↓
Edge
  ↓
Node
  ↓
State
```

也就是：

> **把 Agent 当成一个“状态机 / 图”。**

例如：

```text
用户问题
   ↓
Research
   ↓
分析
   ↓
需要补充资料？
 ┌─┴─┐
Yes  No
 ↓    ↓
Search  ↓
 ↓      ↓
 └──→ Answer
```

### 优点

- 控制力极强
- 状态管理强
- 支持 checkpoint
- 支持 Human-in-the-loop
- 支持暂停 / 恢复
- 适合复杂 Workflow
- 适合生产环境
- Python / JS 都有生态
- 不强制依赖 LangChain

官方也特别强调它适合 long-running、stateful agents。([GitHub](https://github.com/langchain-ai/langgraph?utm_source=chatgpt.com))

### 缺点

最大的问题：

> **复杂。**

你需要真正理解：

```text
State
Node
Edge
Checkpoint
Interrupt
Persistence
Concurrency
```

所以它更像：

> **Agent 世界里的 Linux。**

自由度非常高，但你得懂它。

### 适合

**生产级复杂 Agent：★★★★★**

例如：

- AI Coding Agent
- 金融审批
- 企业流程自动化
- 多步骤 Research
- Human-in-the-loop
- 长任务 Agent
- 多 Agent Workflow

# 四、第二名：CrewAI

[CrewAI GitHub](https://github.com/crewAIInc/crewAI?utm_source=chatgpt.com)

CrewAI 的核心思想不是“画图”，而是：

> **模拟一个 AI 团队。**

例如：

```text
          Manager
             │
     ┌───────┼───────┐
     ↓       ↓       ↓
 Research  Writer   Reviewer
 Agent     Agent     Agent
```

每个 Agent 有：

```text
Role
Goal
Backstory
```

非常像给 AI 招聘员工。

### 优点

- 非常容易理解
- 多 Agent 非常自然
- 开发速度快
- 非常适合 Demo / MVP
- 角色化 Agent 很直观

### 缺点

最大的缺点：

> **控制力不如 LangGraph。**

当流程越来越复杂：

```text
Agent A
  ↓
Agent B
  ↓
条件判断
  ↓
Agent C
  ↓
失败？
  ↓
回滚？
  ↓
人工审核？
  ↓
重新执行？
```

CrewAI 会开始变得不如 LangGraph 自然。

### 适合

⭐⭐⭐⭐⭐

- Multi-Agent
- 内容生产
- Research
- 市场分析
- AI Team
- MVP

一句话：

> **想快速体验 Multi-Agent，CrewAI 很舒服。**

# 五、第三名：LlamaIndex

LlamaIndex 的核心不是“Agent 编排”。

而是：

> **让 Agent 更好地理解和使用你的数据。**

典型：

```text
             Agent
               │
        ┌──────┼──────┐
        ↓      ↓      ↓
      PDF    DB     API
        ↓      ↓      ↓
      Index  Index  Index
        └──────┼──────┘
               ↓
              RAG
```

所以它特别适合：

> **Data Agent / RAG Agent**

### 优点

- RAG 强
- 文档处理强
- 数据连接能力强
- 企业知识库场景好
- 非结构化数据处理优秀

### 缺点

- 框架比较庞大
- 抽象比较多
- 如果你只是想做一个简单 Agent，会感觉有点重

### 适合

```text
企业知识库
     ↓
RAG
     ↓
Agent
     ↓
SQL / API / 文档
```

如果你的核心问题是：

> “Agent 怎么理解我的企业数据？”

那么 LlamaIndex 非常值得考虑。

# 六、第四名：Pydantic AI

[Pydantic AI GitHub](https://github.com/pydantic/pydantic-ai?utm_source=chatgpt.com)

这个我个人认为是视频里**非常值得程序员关注的一个**。

核心思想：

> **用 Python 类型系统约束 Agent。**

例如传统 Agent：

```text

 ↓
返回一段文本
 ↓
你自己解析
```

Pydantic AI：

```text
LLM
 ↓
Structured Output
 ↓
Pydantic Model
 ↓
Type Validation
 ↓
业务代码
```

官方目前把它定位为 typed、extensible 的 Python AI SDK，并强调模型无关、MCP、durable execution、evals 等能力。([GitHub](https://github.com/pydantic/pydantic-ai/?utm_source=chatgpt.com))

### 优点

- 类型安全
- Python 开发体验好
- Model-agnostic
- 支持大量模型供应商
- 非常适合后端工程
- 代码比较干净
- 测试和验证能力强

### 缺点

它不是：

> “我帮你自动把 20 个 Agent 编排起来。”

所以复杂 Multi-Agent Workflow：

**LangGraph > Pydantic AI**

### 适合

```text
FastAPI
   +
Pydantic
   +
Agent
   +
数据库
   +
API
```

尤其适合：

> **Python 后端工程师。**

# 七、第五名：Dify

[Dify GitHub](https://github.com/langgenius/dify?utm_source=chatgpt.com)

Dify 和前面几个其实不是一个层级。

它更像：

> **AI 应用开发平台。**

而不是单纯 Python Agent SDK。

典型开发方式：

```text
         Dify
          │
   ┌──────┼──────┐
   ↓      ↓      ↓
 Workflow RAG   Agent
   │      │      │
   └──────┼──────┘
          ↓
        API
          ↓
       你的 App
```

Dify 官方目前提供：

- Visual Workflow
- RAG
- Agent
- Model Management
- LLMOps
- API
- 可观测性
- Self-hosting

([GitHub](https://github.com/langgenius/dify/blob/main/README.md?utm_source=chatgpt.com))

### 优点

**最大优点：快。**

你不需要先写：

```python
class Agent:
    ...
```

而是：

```text
拖节点
 ↓
连线
 ↓
配置模型
 ↓
配置 Prompt
 ↓
发布 API
```

### 缺点

最大的缺点就是：

> **抽象能力受平台限制。**

简单东西非常快。

复杂东西：

```text
Dify
 ↓
发现做不到
 ↓
写 Plugin
 ↓
写代码
 ↓
最后又回到代码框架
```

所以：

### Dify

适合：

**业务团队 / MVP / 企业内部 AI 应用**

而不是：

**Agent Framework 研究 / 深度自定义编排**

# 十五、我对这期视频的一个重要补充

视频里有一个观点我非常赞同：

> **未来 Agent Framework 的核心竞争力，不再是“我能不能调用 Tool”。**

因为 MCP 正在解决这个问题。

未来真正重要的是：

```text
             Agent
               │
       ┌───────┴────────┐
       ↓                ↓
 Context              Tools
 Engineering           │
       │               MCP
       ↓
 Memory
       │
       ↓
 Planning
       │
       ↓
 Orchestration
       │
       ↓
 Multi-Agent
       │
       ↓
 Production
```

所以我会把 Agent Framework 的核心能力理解成：

> **模型只是“大脑”，Tool 是“手”，MCP 是“USB”，而 Framework 真正负责的是“如何让整个身体协调工作”。**

这也是为什么 **LangGraph 的价值越来越明显**--它并不是让模型变聪明，而是让你能够**控制一个复杂 Agent 系统怎么运行**。([GitHub](https://github.com/langchain-ai/langgraph?utm_source=chatgpt.com))
